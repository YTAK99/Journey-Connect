### [검증 결과 분석]
- **확인된 사실 & 실패 항목**: 프론트 린트·빌드, 백엔드 컴파일, DB 비의존 단위 테스트 12건은 통과했고 사용자가 실행한 전체 백엔드 테스트도 성공했습니다. 브라우저 검증에서 다음 문제가 확인됐습니다.
    1. **높음 — 목록 응답 계약 불일치**: [PostDtos.java](E:/STUDY/Journey-Connect/jc-backend/src/main/java/com/jc/backend/post/PostDtos.java:53)의 목록 응답에는 `content`, `liked`, `bookmarked`가 없지만 [FeedCard.jsx](E:/STUDY/Journey-Connect/jc-frontend/src/components/FeedCard.jsx:39)와 [PostCard.jsx](E:/STUDY/Journey-Connect/jc-frontend/src/components/PostCard.jsx:17)가 사용합니다. 본문 미리보기가 비고, 본문에만 검색어가 있는 결과가 프론트 재필터링에서 사라지며, 좋아요·북마크 상태가 새로고침 후 초기화될 수 있습니다.
    2. **높음 — 계정 복구 미구현**: [auth.js](E:/STUDY/Journey-Connect/jc-frontend/src/services/auth.js:61)의 아이디·비밀번호 찾기는 항상 `null`이며 백엔드 API도 없습니다. 비밀번호 원문을 알림으로 보여주려는 현재 화면 설계는 보안상 사용할 수 없습니다.
    3. **중간 — 마이페이지 인증·저장 오류**: 비로그인 상태에서도 [App.jsx](E:/STUDY/Journey-Connect/jc-frontend/src/App.jsx:54)의 마이페이지에 접근해 `사용자` 프로필이 표시됩니다. [MyPage.jsx](E:/STUDY/Journey-Connect/jc-frontend/src/pages/MyPage.jsx:40)의 프로필 저장은 화면 상태만 변경하며 백엔드에 저장되지 않습니다.
    4. **중간 — 인증 갱신 미연동**: Refresh Token을 저장하지만 재발급 API를 호출하지 않아 Access Token 만료 시 즉시 로그아웃 처리됩니다.
    5. **중간 — 주요 버튼 미연동**: 스토리 항목은 상세 이동이 없고 [StoryList.jsx](E:/STUDY/Journey-Connect/jc-frontend/src/components/StoryList.jsx:55), 댓글 아이콘도 동작이 없습니다. 크루 화면은 [CrewPage.jsx](E:/STUDY/Journey-Connect/jc-frontend/src/pages/CrewPage.jsx:7)의 샘플 데이터와 로컬 참가 상태만 사용하며 크루 생성 버튼도 동작하지 않습니다.
    6. **중간 — 피드 상태 전환 위험**: 검색어가 변경돼도 `loading`과 `error`를 초기화하지 않아 이전 빈 결과를 기준으로 탐색 화면에 먼저 이동하거나, 한 번 발생한 오류가 성공 후에도 남을 수 있습니다.
    7. **중간 — 검색 초기화 반복 가능성**: 탐색 화면의 초기화는 선택 지역을 유지한 채 `/feed`로 이동합니다. 해당 지역에 글이 없으면 피드가 다시 탐색으로 자동 이동해 초기화 버튼이 사실상 동작하지 않습니다.
    8. **중간 — 다국어 적용 불완전**: 브라우저에서 영어로 변경해도 크루·마이페이지·인증 화면 등은 한국어로 남았습니다.
    9. **낮음 — 이동 정보 중복**: 서울 fallback 값 때문에 `인천공항 기준 서울 기준`, 영어에서는 `From Seoul from Incheon Airport`로 표시됩니다. 원인은 [regions.js](E:/STUDY/Journey-Connect/jc-frontend/src/data/regions.js:13)와 [LocationWeather.jsx](E:/STUDY/Journey-Connect/jc-frontend/src/components/LocationWeather.jsx:341)의 문구 중복 조합입니다.
    10. **검증 공백**: 프론트엔드 자동 테스트 스크립트가 없고, 프로덕션 번들은 약 819KB로 코드 분할 경고가 발생합니다.

- **원인 후보 & 우선 확인 사항**: 가장 먼저 게시글 목록 DTO와 카드가 기대하는 필드를 일치시켜야 합니다. 다음으로 계정 복구·라우트 보호·프로필 저장·토큰 재발급을 하나의 인증 범위로 정리해야 합니다. 크루·댓글·스토리는 백엔드 기능은 존재하지만 프론트가 샘플 또는 정적 UI 단계에 머물러 있습니다.
- **최소 수정 방향 & 재검증 방법**: 1. 목록 응답에 안전한 본문 미리보기와 사용자별 반응 상태를 제공하거나 프론트 의존을 제거하고, 본문 검색·새로고침 반응 상태를 통합 검증합니다. 2. 계정 복구 화면은 비밀번호 재설정 방식으로 새로 설계하고 마이페이지 인증 가드·프로필 API·토큰 갱신을 연결합니다. 3. 스토리 상세 이동과 댓글을 연결하고, 크루 기능은 실제 API 연결 전까지 버튼을 비활성화하거나 준비 중으로 표시합니다. 4. 피드 요청 상태와 검색 초기화 동작을 수정한 뒤 빈 지역·검색어 변경·뒤로 가기를 재검증합니다. 5. 다국어 누락과 서울 이동 문구를 정리합니다. 검증 과정에서는 DB 데이터나 업로드 파일을 생성하지 않았으며, 언어 설정을 한국어로 원복하고 브라우저 탭과 개발 서버도 모두 종료했습니다.
